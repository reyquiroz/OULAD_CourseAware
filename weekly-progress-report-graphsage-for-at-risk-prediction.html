A. What I Have Completed

1. Completed the GraphSAGE data flow

The two-layer EnrollmentGNN now consumes all available behavioral attributes. Assessment scores (submitted edge), VLE click features (total_clicks, n_interactions, first_day, last_day, active_days on interacted_with edges), and enrollment metadata (age_band, num_of_prev_attempts, studied_credits) are each projected to 64-d via separate linear layers, scatter-aggregated to student nodes, and added to the student representation between the two SAGEConv layers. All numeric features are normalized (z-score; log1p before standardization for click counts) inside the graph loader.

  • Three edge-attribute projection layers (enrollment_attr_proj, submitted_attr_proj, interacted_with_attr_proj) feeding into message passing
  • Feature normalization applied globally (over the full graph, not per split) before any model sees the data
  • Prediction unit remains the enrolled_in edge — one probability per enrollment, 32,593 total — so students with multiple enrollments receive independent predictions without label ambiguity

2. Corrected the LCPO evaluation protocol

Two protocol bugs were found and fixed before the full experiment run:

Masking bug (over-filtering). The previous code removed all submitted and interacted_with edges for any student enrolled in the held-out course, including their activity in other courses. The fix filters by destination node instead: only edges whose target assessment or VLE resource belongs to the held-out course-presentation are removed. Students enrolled in multiple courses retain their cross-course behavioral signal.

Early-stopping failure (epoch 4). Both initial LCPO folds stopped at epoch 4 out of 200. The student-grouped 10% validation draw was producing fewer than 20 positive examples for small course-presentations, causing AUROC to fluctuate and early stopping to trigger immediately. The fix adds a min_val_pos=20 guarantee with a fallback to enrollment-indexed sampling at increasing fractions (10%→30%) until the minimum is met. LCPO patience was also raised from 20 to 50 epochs. After the fix, best_epoch ranged from 79 to 199 across folds.

  • LCPO masking corrected to destination-node filter (cross-course signal preserved)
  • Validation minimum at-risk guarantee with progressive fallback
  • Student-grouped validation draw retained where the minimum is met; enrollment-indexed fallback otherwise
  • LCPO patience raised to 50; random-split patience unchanged at 20

C. What Problems Have I Encountered?

Problem 1 — LCPO early stopping at epoch 4 fixed

Both initial LCPO folds stopped at epoch 4 with a best validation AUROC of only 0.69. The student-grouped 10% validation draw for small course-presentations (AAA, ~370 test enrollments) produced fewer than 20 positive examples in the validation set, causing the AUROC signal to be unstable. Early stopping interpreted the first marginal improvement as the best checkpoint and halted training before the optimizer had converged.

Fix applied: Added a min_val_pos=20 check after the validation draw; falls back to enrollment-indexed random sampling at increasing fractions (10%→30%) if the minimum is not met. LCPO patience raised from 20 to 50. After the fix, best_epoch for the same two folds became 138 and 199.

Problem 2 — LCPO masking stripped cross-course behavioral data fixed

The original _mask_held_out_edges() function identified held-out students by node index and removed all their submitted and interacted_with edges — including edges connecting those students to other courses they were also enrolled in. This impoverished the held-out students' graph representations during training, making the LCPO condition harder than it needs to be and inconsistent with how the model would be used at deployment (where a student's history from other courses would be available).

Fix applied: Filter by destination node. A submitted edge is removed only if its target assessment belongs to the held-out course-presentation (reachable via contains_assess). An interacted_with edge is removed only if its target VLE resource belongs to the held-out CP (reachable via has_resource). Cross-course edges are preserved.

Problem 3 — High fold-to-fold variance in LCPO open

AUROC ranges from 0.705 (GGG 2013J) to 0.904 (FFF 2014J) across the 22 folds, and the standard deviation is 0.063. This reflects genuine course difficulty variation rather than model instability — LightGBM shows a similar range (0.641–0.890, std 0.075). The GGG module is consistently the hardest for both models, with near-random precision and very high recall, suggesting that at-risk students in GGG are difficult to distinguish from passing students using the available features. No fix is attempted yet; this is treated as a finding for the report.

Problem 4 — LightGBM LCPO gaps are inconsistent across comparison runs monitoring

The comparison_results.csv file shows LightGBM LCPO mean AUROC of 0.824 (current full run) vs. 0.783 in the earlier partial summary. Both numbers use the same 22-fold file and the same feature set; the difference likely reflects that the earlier summary was computed over the first 2 AAA folds only (which are the hardest). The current 22-fold summary is the correct reference. The AAA-only 2-fold result should not be cited.

Priority 2 — Threshold recalibration for LCPO

The current LCPO threshold is selected on the in-distribution validation set, which comes from the same course mix as training. For an out-of-distribution test course, the optimal threshold may differ. Planned experiment: apply the LCPO-trained model to the held-out fold, sweep thresholds on a small held-out-course-specific calibration set (first 10% of held-out enrollments, sorted by enrollment order), and compare F1 / balanced accuracy against the in-distribution threshold. If recalibration helps, it should be incorporated as a post-processing step.

Priority 3 — Investigate GNN advantage on GGG and AAA courses

The GNN wins most on GGG and AAA, which are also the courses where both models perform worst. Understanding why (course size, student population, assessment structure, VLE usage patterns) may reveal what aspect of the graph representation provides the advantage. A short exploratory analysis querying the graph validation summaries and course-level statistics is planned.
